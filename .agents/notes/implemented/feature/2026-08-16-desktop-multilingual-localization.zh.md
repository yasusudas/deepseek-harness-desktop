# Agent Note: 桌面端多语言本地化与 Auto 选择

Status: implemented

[English](2026-08-16-desktop-multilingual-localization.md) | 中文

## 问题

桌面封装此前只向上游浏览器客户端补入一份日语词典，而上游仅附带简体中文和英语。语言设置只能持久化一个明确语言，浏览器检测只比较主语言子标签，共享界面字体栈还优先使用简体中文字形。若沿用日语补丁的方式逐个加入繁体中文、韩语、西班牙语、巴西葡萄牙语、德语和法语，会复制运行时修改逻辑、错误判断中文地区，也无法在界面上区分“来自 macOS 的语言”和“用户固定选择的语言”。

## 决策

桌面封装使用一份语言清单和一个构建时补丁程序。清单定义九个随附语言标识、自语言名称及针对各语言的 macOS 系统字体栈。每个新增语言都有与 `ja.json` 键集合一致的命名空间词典，以及与 `static-ja.json` 键集合一致的静态短语词典；`verify-localizations` 会在替换或下载 bundle 前拒绝命名空间缺失、键缺失或多余、空值以及 `{placeholder}` 集合变化。

语言设置把 `auto` 作为界面选择而非可持久化的 `LocaleId`。选择 Auto 会删除 Host 的 `preference` 字段；选择明确语言则写入其语言标识，即使其当前有效语言与 Auto 相同。语言快照因此同时发布有效的 `active` 语言和 `selection`。选择器可以据此显示本地化的「系统设置」文案且不插入检测到的语言名称，保留自动与固定选择的区别，并在只有该区别变化时刷新。

Auto 在应用启动时解析浏览器提供的有序语言列表。`zh-TW`、`zh-HK`、`zh-MO` 和 `zh-Hant` 变体映射为 `zh-Hant`；简体中文变体映射为 `zh`；只有 `pt-BR` 映射为巴西葡萄牙语；其他随附语言通过主语言子标签接受地区变体。不支持的语言列表回退到英语。macOS 语言变更在下次启动应用或重新加载浏览器时生效，不会在用户使用过程中突然改变当前会话。

桌面封装使用带版本的 localStorage 标记，使此版本首次启动时默认采用 Auto。安装或升级后的第一次浏览器启动会清除旧版 Host 语言偏好一次；写入标记后，用户明确选择的语言会在重启后保持不变。

运行时为每个有效语言设置 `document.documentElement.lang`。主题对日语使用 Hiragino Sans，对简体中文使用 PingFang SC，对繁体中文使用 PingFang TC 或 HK，对韩语使用 Apple SD Gothic Neo。拉丁文字语言继续使用现有 macOS 系统字体栈，代码继续使用现有等宽字体栈。静态短语替换被推广到所有新增语言，但仍排除代码、Markdown 输出、可编辑内容和对话气泡。

## 曾考虑的替代方案

**把 `auto` 作为另一个语言标识持久化。** 已否决：Auto 是偏好模式而不是词典；存储它会削弱 Host schema，并迫使每条查询路径特殊处理一个并非语言的值。

**只解析一次 Auto 并持久化解析结果。** 已否决：应用将无法跟随后续 macOS 语言变化，也无法显示当前语言究竟是自动选择还是固定选择。

**把所有葡萄牙语地区标签映射为 `pt-BR`。** 已否决：随附的产品语言是巴西葡萄牙语，将欧洲葡萄牙语静默视为巴西葡萄牙语会作出错误的地区选择。

**随应用打包第三方 Web 字体。** 已否决：目标平台是 macOS，系统字体已覆盖所有随附文字并提供原生排版度量，无需增加下载、许可证或应用体积成本。

## 后果

桌面语言菜单会在九个明确语言之前显示动态 Auto 选项，并能在下次启动时跟随 Mac 的首选语言。带版本的首次启动标记让全新安装或升级后进入 Auto，同时不会重置之后明确选择的语言。构建会在修改附带运行时之前暴露词典漂移，一条补丁路径统一负责语言注册、静态短语、检测、选择状态和字体选择。桌面封装仍会补丁固定的上游版本，因此上游编译产物变化时标记检查会刻意失败；更新固定的 Harness 版本时必须针对新的客户端产物复核并调整补丁。
